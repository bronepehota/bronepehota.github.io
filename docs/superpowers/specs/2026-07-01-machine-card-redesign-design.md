# Редизайн карточки машины: цельность и очевидность — дизайн (#179)

**Дата:** 2026-07-01
**Issue:** [#179 — Редизайн карточки машины: цельность и очевидность (на уровне солдатской)](https://github.com/Luxor/bronepehota/issues/179)
**Тип:** enhancement / usability (UI-редизайн)
**Scope:** визуальная переборка карточки машины в единый цельный модуль (mobile-first). **Только UI/UX** — боевая механика и данные не меняются.

## Контекст и расследование

Фидбек игрока: экран машины «довольно неочевидный и более слабый по сравнению с солдатским».
`SoldierCard` — один цельный компонент (одна рамка, uniform stat-бейджи, одна явная точка входа в
действия). Карточка машины — стопка отдельных панелей, действие разбросано.

**Активный рендер `MachineView.tsx`** (`src/components/cards/unit-card/MachineView.tsx`) — это
стопка из **3** компонентов + disabled-кнопка «Таран»:

1. `TacticalDashboard` (300 строк) — изображение + прочность + скорость + пилот + alert-полоса
   теста пилота (#163). Уже поглотил статусы, но сидит отдельной «приборной» панелью с тактической
   сеткой, scan-line и уголками.
2. `MachineAmmoPanel` (186) — боезапас + выстрелы + (для community) боезапас по орудиям.
3. `MachineWeaponsList` (171) — оружия (тап = выстрел) + ближний бой (ББ).

**Мёртвый код** (не импортируются нигде в `src/components`, живы только юнит/a11y-тестами):
`MachineStatsPanel.tsx` (110), `MachinePilotPanel.tsx` (90), `MachineImage.tsx` (39). Issue считает
«6 панелей / ~896 строк», но ~240 строк — мёртвый тест-only код.

**Главное UX-противоречие с солдатом:** у солдата — одна точка входа в действия (клик по центру →
«Выберите действие»). У машины действия разбросаны: атака = клик по строке оружия; урон/ремонт =
кнопки в прочности; тест пилота = alert-полоса; таран = disabled. Атака по природе **привязана к
оружию** (у каждого свои дальность/мощность/особенности), поэтому «одна кнопка атаки» не ложится
чисто — правильнее **выделить оружия как явную главную зону действий**.

### Исследованные альтернативы (через визуальные мокапы)

- **Эстетика:** «Тактический HUD» (очищенный) vs «Чистая сетка как у солдата» → выбрана **чистая
  сетка** (меньше хрома, больше воздуха, uniform-бейджи, единая рамка).
- **Точка входа в действия:** «оружия как главное действие» vs «единая кнопка Действия» vs «ряд
  крупных action-кнопок» → выбраны **оружия как главное действие** (естественная модель, без лишних
  тапов, переиспользует логику).
- **Пилот:** inline-раскрытие vs таб vs **bottom-шторка** → выбрана **шторка** (консистентно с
  боевой шторкой и модалками пилота/паники; карта не двигается).

## Решение

### 1. Одна цельная карточка (направление «чистая сетка»)

`MachineView.tsx` рендерит **один** контейнер: одна рамка (`border` + `rounded-xl` + единый
`padding`), секции разделены интервалами/тонкими хейрлайнами — **не** отдельными панелями с
повторными `bg-slate-900/60 p-1.5 rounded-sm border` + уголками. Убирается тактическая
сетка/scan-line/corner-brackets (оставляем только skull-оверлей на уничтоженной машине).

**Иерархия (вертикаль, mobile-first ~390px):**

1. **Статус-хедер** (flex): изображение машины (слева, **~95px** mobile, aspect 3/4 — чуть крупнее
   текущих 90px; пилот-портрет убран из хедера в чип, поэтому горизонтального места стало больше;
   тап по фото → полноэкранный просмотр, как сейчас) | грид uniform-бейджей: **Прочн** `8/10`
   (цвет зоны), **Скор** `4 ш`, **чип пилота** (на всю ширину, см. §3).
2. **Сегментированный бар прочности** (цвет зоны: green/yellow/red).
3. **Alert-полоса теста пилота** (#163) — только когда активна (см. §4), prominence поверх всего.
4. **Оружия** — главная зона действий: заголовок «нажмите, чтобы стрелять» + индикатор
   `выстрелы N/M`; крупные tappable-строки (имя + ◎ дальность ▲ мощность + ⓘ); под каждым дальнобойным
   орудием — мини-бар боезапаса (community). Строка «стрелял» — амбер-тинт.
5. **Ближний бой (ББ)** — компактная секция, если есть ББ-оружия.
6. **Вторичные действия:** `−1 Урон` / `+1 Ремонт` (крупные кнопки).
7. **Боезапас** (глобальный бар + `N/M` + кнопки ± для Tehnolog).

### 2. Компонентная структура

- **`MachineView.tsx`** — контейнер: один cohesive-карточный div, раскладка секций, проброс
  колбэков. Удаляется блок кнопки «Таран» и расчёт `meleeBonus` (использовался только для неё).
- **`TacticalDashboard.tsx` → переименовать в `MachineStatusHeader.tsx`** (импортируется только из
  `MachineView` — churn минимальный): хедер (§1) + бар прочности + alert-полоса (§3/§4). Очистка
  HUD-хрома, переход на uniform-бейджи. **Сохраняет test-id `assign-pilot-button` (на чипе пилота) и
  `pilot-survival-test-button` (на alert-полосе)** — их ждут E2E (#163 defender-тест,
  `pilot-functionality.spec.ts`).
- **`MachineWeaponsList.tsx`** — рестайл в крупные чистые строки; **впитывает мини-бары боезапаса по
  орудиям** (раньше были в `MachineAmmoPanel`) под каждым дальнобойным орудием (community). Логика
  disabled (`totalShotsUsed >= fireRate` / нет патронов), `onWeaponAttack`/`onWeaponInfo`, сплит
  ranged/melee — без изменений.
- **`MachineAmmoPanel.tsx`** — худеет до глобального бара боезапаса + индикатора выстрелов + кнопок
  ± (Tehnolog). Per-weapon ammo переезжает в `MachineWeaponsList`.
- **`PilotChip.tsx`** (новый) — компактный индикатор пилота в хедере. Состояния: «Пилот назначен ·
  ЖИВ» / «ПОГИБ» (красн.) / «Пилота нет · назначить». Тап → `onOpenPilot()`.
- **`PilotSheet.tsx`** (новый) — bottom-sheet (через `useBottomSheet`): портрет + статус
  (ЖИВ·броня / ПОГИБ) + «⚠ Тест пилота» (`onSurvivalTest`) + «Сменить» (`onAssignPilot` → существующий
  `PilotAssignmentModal`).

### 3. Поведение пилота (компактный чип → шторка)

- **Пилота нет:** тап по чипу → `onPilotAssign()` (сразу `PilotAssignmentModal`, без пустой шторки).
- **Пилот жив:** тап → `PilotSheet` (портрет, «ЖИВ · броня N», «Тест пилота», «Сменить»).
- **Пилот погиб:** тап → `PilotSheet` в состоянии ПОГИБ (без кнопки теста; «Сменить»).
- Портрет пилота **не показывается постоянно** — только в шторке (экономит вертикаль, меньше хрома).

### 4. Маркер теста пилота после урона (#163)

Логика без изменений: `UnitCard.pilotTestUrgent` взводится при **снижении** `unit.currentDurability`
(машина + живой пилот). Рендерится в `MachineStatusHeader` как **полноширинная амбер-полоса**
(пульс), prominence сразу под хедером; тап → `onSurvivalTest`. После теста — зелёная «✓ ВЫЖИЛ» /
красная «✗ ПОГИБ». Idle — скрыта. **Заметна даже при свёрнутом пилоте.**

### 5. Удаление мёртвого кода и UI

- Удалить `machine-view/MachineStatsPanel.tsx`, `machine-view/MachinePilotPanel.tsx`,
  `machine-view/MachineImage.tsx` (+ перед удалением — `grep` по `src/`, убедиться что нет
  импортёров помимо тестов).
- Удалить кнопку «Таран» (disabled/«СКОРО», не реализована — мёртвый UI). Ближний бой (ББ) остаётся
  в `MachineWeaponsList`.
- Удалить `meleeBonus`-расчёт в `MachineView` (служил только метке «Таран»).

## Non-goals

- Боевая механика / данные / `executeShot` / зонный урон / `calculateDamage` — не трогаем.
- Кнопка «Таран» как **функциональность** (её нет) — не возвращаем; если появится реальная механика
  тарана, это отдельная задача.
- Переписать `MachineView` с нуля — нет: переиспользуем и объединяем существующие панели.
- Редизайн `SoldierCard` / `SquadView` / `UnitCardHeader` — вне рамок.

## Краевые случаи

- **Нет изображения:** fallback «Нет изображения» (чистый стиль) вместо сломанной рамки.
- **Машина уничтожена** (прочность 0): `UnitCard` уже накладывает grayscale/opacity; skull-оверлей
  на изображении остаётся; чип/действия не активны.
- **Пилота нет / мёртв:** alert-полоса теста не взводится (`pilotInfo?.alive` false); чип показывает
  соответствующее состояние.
- **Mount с повреждённой машиной:** `pilotTestUrgent` не взводится исторически (`prevDurabilityRef`
  инициализирован текущей) — как в #163.
- **community Star System (per-weapon ammo):** мини-бары под каждым дальнобойным орудием; глобальный
  бар показывает итог. Tehnolog — единый пул + кнопки ±.
- **`fire_rate` исчерпан / нет патронов:** строки оружий disabled (opacity, `cursor-not-allowed`).
- **Шторка пилота + боевая модалка:** «Сменить» открывает `PilotAssignmentModal` поверх закрытой
  шторки (закрывать шторку перед модалкой, чтобы не было двух оверлеев).

## Критерии приёмки

- [ ] Карточка машины — **единый цельный модуль** (одна рамка/padding, не стопка разрозненных
      панелей); меньше визуального хрома (без тактической сетки/scan-line/уголков).
- [ ] Чёткая иерархия: **статус → оружия(действия) → урон/ремонт → боезапас**; оружия — очевидная
      крупная tappable зона «тап = выстрел».
- [ ] **Mobile-first:** читаемость на 390px, больше воздуха.
- [ ] **Пилот:** компактный чип → шторка (портрет/тест/смена); портрет не торчит постоянно.
- [ ] **Маркер теста пилота после урона (#163)** — заметная амбер-полоса, даже при свёрнутом пилоте.
- [ ] Вся функциональность сохранена (прочность/зоны/скорость/боезапас общий и по орудиям/оружия/
      пилот/тест). «Таран» (не реализован) — удалён как мёртвый UI.
- [ ] **Мёртвый код удалён** (`MachineStatsPanel`, `MachinePilotPanel`, `MachineImage`) + их тесты.
- [ ] `npm run validate` + `npm run test:e2e` зелёные; test-ids `assign-pilot-button`,
      `pilot-survival-test-button` сохранены.

## Риски

- **Переименование `TacticalDashboard` → `MachineStatusHeader`:** импортируется только из
  `MachineView` — churn минимальный; можно не переименовывать, если имя не критично (но имя «лжёт»
  после очистки HUD).
- **`PilotSheet` — новый интеракшн:** следить за совместной работой с `PilotAssignmentModal`
  («Сменить» открывает модалку — закрывать шторку, без двойных оверлеев).
- **Перенос per-weapon ammo** в `MachineWeaponsList`: проверить корректность итога для community
  (сумма + по орудиям) — не сломать `usePerWeaponAmmo`-ветку.
- **a11y-тест:** при перепривязке утверждений не потерять 44px-покрытие кнопок.

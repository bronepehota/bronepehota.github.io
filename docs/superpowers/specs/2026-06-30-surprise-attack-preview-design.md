# «С тыла»: правильное превью + визуализация двойного броска мощности — дизайн (#174)

**Дата:** 2026-06-30
**Issue:** [#174 — «С тыла» (внезапная атака): убрать завышение вероятности попадания + визуализировать двойной бросок мощности](https://github.com/Luxor/bronepehota/issues/174)
**Тип:** bug (правила / UI-превью)
**Scope:** превью боя (hit/penetration probability) + нотация мощности в combat-модалке. Фактический бой (`executeShot`) НЕ меняется — он уже корректен.

## Контекст

Правило §8.3 «Внезапная атака» (и Tehnolog, и Star System v0.3), дословно:

> Если пехотинец или боевая машина атакует противника с тыла, то защищающийся «не видит» атаки. В этом случае **при подсчёте Силы атаки** своего воина (машины) атакующий игрок может **бросить кубик два раза и выбрать для подсчёта наибольший результат**. Кроме того, если внезапной атаке подверглась боевая машина, то при подсчёте Силы этой машины в Защите не учитывается её ББ.

Сила атаки = мощность/урон. Двойной бросок относится к **мощности**, а не к попаданию.

## Корневая причина (текущее состояние — внутренне противоречиво)

`HitProbabilityIndicator` показывает две полосы + тултип:

| Элемент | Сейчас | Правильно ли |
|---------|--------|--------------|
| ПОПАДАНИЕ (hit) | `calculateHitProbability(..., isSurpriseAttack)` применяет «roll twice, take best» к **попаданию** → % завышен | ❌ не должен зависеть от surprise |
| ПРОБИТИЕ (мощность vs броня) | `calculatePenetrationProbability(...)` surprise **не учитывает** → % не отражает двойной бросок | ❌ должен отражать best-of-2 |
| Тултип | «Бросок x2, лучший результат» — висит у попадания | перепривязать к мощности |

Фактический бой прав: `executeShot` перебрасывает **урон** (`calculateDamage` дважды → лучший, `useCombatFlow.ts:297–313`), `calculateHit` идёт без surprise (`:280–285`, комментарий `// surprise attack doesn't affect hit roll`). Данные двойного броска уже собираются: `damageResult.bothRolls`, и `CombatResults.tsx:191–215` УЖЕ отрисовывает «Бросок 1 / Бросок 2» с подсветкой победителя.

**Т.е. двойной бросок применили не к той полосе превью (к попаданию вместо мощности).**

## Цели

1. **ПОПАДАНИЕ** — обычная вероятность (single-roll); не завышается при «с тыла».
2. **ПРОБИТИЕ (мощность)** — отражает двойной бросок: вероятность пересчитывается как **best-of-2**.
3. **Визуализация «макс» на мощности** — нотация/бейдж «макс» при surprise (shot), напр. мощность «2D6» → «2D6 макс».
4. **Результаты** — оставить viz `bothRolls` (уже корректно; возможно мелкий polish — в плане).
5. **Тултип** «максимум» — перепривязать к мощности.

## Дизайн

### 1. `calculateHitProbability` — убрать surprise-ветку

`src/components/combat/HitProbabilityIndicator.tsx:36`. Удалить ветку `if (!isSurpriseAttack) {...} /* surprise: roll twice */`. ПОПАДАНИЕ всегда считается как single-roll (тот же код, что сейчас в `!isSurpriseAttack`-ветке). Параметр `isSurpriseAttack` из сигнатуры `calculateHitProbability` убирается (больше не нужен).

### 2. `calculatePenetrationProbability` — добавить best-of-2

`HitProbabilityIndicator.tsx:99`. Добавить параметр `isSurpriseAttack: boolean = false`. При `true` вероятность и ожидаемое число пробивающих кубиков пересчитываются как **best-of-2** (на per-die-метрике):

- `p = favorableOutcomes / sides` (per-die penetration chance, как сейчас).
- `pBest = 1 − (1 − p)²` (шанс, что лучший из 2 бросков кубика пробивает).
- `probability = pBest × 100`.
- `penetratingDice = dice × pBest`.

Точно для однокубиковой мощности (1D-бросок ×2 → лучший); для многокубиковой — разумная аппроксимация «лучший из 2 на кубик» (≈ +9% к ожидаемому vs точный «лучший пул», приемлемо для превью). Отметить в комментарии.

### 3. `HitProbabilityIndicator` — правильно раздать surprise

- `calculateHitProbability(rangeStr, distance, fortification, rulesVersion)` — **без** surprise (ПОПАДАНИЕ = обычная).
- `calculatePenetrationProbability(powerStr, armor, fortification, rulesVersion, isSurpriseAttack)` — **с** surprise (ПРОБИТИЕ = best-of-2).
- Тултип показывает «мощность: максимум» у ПРОБИТИЕ/мощности (не у попадания). У попадания — обычный «Нужно бросить ≥N».
- «макс»-бейдж на полосе ПРОБИТИЕ при surprise.

### 4. Нотация мощности «макс» — `ParameterInputs`

`src/components/combat/ParameterInputs.tsx` (DiceNotationDisplay мощности, ~`:236/239`). При `parameters.isSurpriseAttack && actionType === 'shot'` показывать мощность с маркером двойного броска — напр. аннотация/бейдж «макс» рядом с нотацией (текст «2D6 макс» или бейдж «макс (с тыла)»). НЕ менять саму roll-строку, парсимую `DiceNotationDisplay` (добавлять визуальный маркер рядом, не внутрь `2D6`).

### 5. Результаты боя — без изменений

`CombatResults.tsx:191–215` уже отрисовывает `bothRolls` («Бросок 1» / «Бросок 2», победитель purple). Оставить как есть (если в ходе реализации виден мелкий polish — optional).

## Non-goals

- **Фактический бой** (`executeShot`, переброс урона) — НЕ трогаем, он корректен.
- Дополнительное правило про ББ машины-защитника (§8.3) — про Силу в защите, ближе к melee; вне scope этого фикса превью.
- Точный расчёт «лучшего из 2 пулов» для многокубиковой мощности — используем аппроксимацию (per-die best-of-2); точный — отдельной задачой при необходимости.

## Краевые случаи

- **`isSurpriseAttack` выкл** — всё как сейчас (ПОПАДАНИЕ и ПРОБИТИЕ single-roll, без маркера). Регрессии нет.
- **Standalone-калькулятор** — `HitProbabilityIndicator`/`calculatePenetrationProbability` общие; фикс применяется везде консистентно (rules-агностично).
- **Melee** — surprise в melee (`calculateMeleeWithSurpriseAttack`) отдельный механизм; превью penetration относится к выстрелу. Не конфликтует.
- **Многокубиковая мощность** — аппроксимация per-die best-of-2 (см. §2); отмечено в комментарии.

  - `calculatePenetrationProbability` при surprise = best-of-2 (`pBest = 1−(1−p)²`), **выше** single-roll; без surprise — прежняя.
- **E2E** (новый `e2e/surprise-attack-preview.spec.ts`): в shot-модалке при включении «с тыла» — % ПОПАДАНИЯ не меняется, % ПРОБИТИЕ растёт, присутствует «макс» (на мощности/пробитии), тултип у мощности. (D6 случайно — покрываем UI/значения превью.)

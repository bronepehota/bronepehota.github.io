# Расширение энциклопедии: оружейные таблицы, индексы БМР/УМ, 4 книги лора, страница «История»

**Дата**: 2026-08-18
**Ветка**: `feat/encyclopedia-novel-lore` (ребейз на `origin/main`, один PR)
**Статус**: дизайн утверждён пользователем (все 3 секции)

## Контекст и проблема

1. **Расширенные данные машин не показываются на проде.** ТТХ-поля
   (`manufacturer/monoblock/mass/crew/type`) лежат в
   `src/data/encyclopedia/units/*/machines.json` у ~28 машин, но на `main` их
   никто не рендерит — компонент `<UnitSpecs>` + «Читать подробнее»
   (`<UnitLoreDetail>`) существуют только на локальной (не запушенной) ветке
   `feat/encyclopedia-novel-lore` (13 коммитов от 6 авг, 35 позади main).
2. **Четыре книги лора не обработаны**: «Имперские войны», «Косары»,
   «Летопись: Звёздные герои», «Штурмовики Протектората»
   (`~/Documents/BP/*.pdf`).
3. В 64-страничном «Справочнике техники» остались неимпортированными
   **таблицы вооружений** (53 блока «Вооружение») и **система обозначений**
   БМР/УМ.

Декод справочника: `pdftotext -raw` даёт UTF-8-мojибейк (cp1251 → latin-1 →
UTF-8); восстановление — посимвольный раундтрип `≤U+00FF → байт → cp1251`,
реальные Unicode-символы (–, ") проходят насквозь. Готовый текст:
`/tmp/handbook_utf8.txt` (~210К).

## Решения (зафиксированы пользователем)

| Вопрос | Решение |
|---|---|
| Судьба ветки | Ребейзнуть на `origin/main`, продолжать на ней, один PR |
| Данные машин | Таблицы вооружений + индексы БМР/УМ + моноблоки-прозвища |
| «Летопись» | Отдельная страница `/encyclopedia/history` |
| Новые сущности | Не заводим: только существующие (фракции, машины, отряды, кампании) + «История». Герои и отряды вне армлистов упоминаются внутри текстов |
| Архитектура данных | JSON-схема в `encyclopedia`-объекте + рендер на карточке (не markdown-таблицы) |

## Секция 1: Данные машин

### Схема (`src/lib/types.ts`)

```typescript
interface ArmamentEntry {
  name: string      // «Двуствольная бронебойная пушка»
  caliber?: string  // «30 мм»
  range?: string    // «400 м» — как в справочнике, строкой
  notes?: string    // боезапас, монтаж
}
// в encyclopedia-объекте машины:
designation?: string        // «БМР-1Г», «УМ-2Ш», «УМ6-2» (Спайдер — цифра)
armament?: ArmamentEntry[]
```

Это **лор-ТТХ**, не игровые статы: не смешивать с `sources/` (кубики,
`ammo_max`). Поле `monoblock` остаётся строкой, значения обогащаются
прозвищем: `"УМ-1 („Сундук")"`, `"РМ-1 („Осьминог")"`.

### UI

- `<UnitArmament>` (`src/components/encyclopedia/UnitDetail/`) — таблица
  «ВООРУЖЕНИЕ» под `<UnitSpecs>`: колонки Орудие / Калибр / Дальность / Прим.
  Пустые колонки скрываются; без `armament` секция не рендерится.
- `designation` — моноширинный чип (`font-ibm-mono`, стиль АВБ-бейджа) рядом
  с типом машины.
- Извлечение: блоки «Вооружение» по 25 машинам справочника, сверка ID с
  энциклопедией по реестру (`docs/ENCYCLOPEDIA_LORE_SOURCES.md`).

### Страница «История»

- Контент: `src/content/history/*.md`, frontmatter `{title, order, era?}` —
  хронология от Тунгусского метеорита до Доминиона (6–9 глав).
- Лоадер `src/lib/history.ts` по образцу `campaigns.ts`: sync
  `getAllHistoryChapters()` (frontmatter, gray-matter) + async body через
  динамически импортированный remark (Jest-импортируемость; unit-тестировать
  только sync-часть).
- Одна страница с якорным оглавлением (не роут на главу), metadata, пункт
  «История» в навигации энциклопедии.
- `app/sitemap.ts` — добавить маршрут.

**Авторские права**: адаптированный пересказ своими словами, не дословный
копипаст (как с «Битвой за Велиан»).

**Реестр**: `docs/ENCYCLOPEDIA_LORE_SOURCES.md` пополняется всеми четырьмя
книгами (что извлечено, куда легло, кредиты).

## Секция 3: Механика, тесты, границы

### Порядок работ

1. `git fetch origin main && git rebase origin/main` — конфликт-зоны:
   `machines.json` фракций (main добавлял dead_fleet/поля); разрешение =
   объединение обеих сторон. `npm run type-check && npm run test` — база
   зелёная. Пуш ветки (первый раз) + черновой PR:
   `git -c credential.helper='!gh auth git-credential' push`.
2. Схема `armament`/`designation` + `<UnitArmament>` + чип.
3. Извлечение таблиц справочника + прозвища моноблоков.
4. «Имперские войны» → кампания + фракции.
5. «Косары» → mercenaries + отряды + глава в «Историю».
6. «Штурмовики Протектората».
7. Страница «История» (лоадер, роут, навигация, sitemap).
8. Реестр источников + финальный `npm run validate`.

### Тесты

- **Unit**: рендер `<UnitArmament>` (скрытие пустых колонок, отсутствие
  секции без данных), чип designation, `getAllHistoryChapters()` (sync),
  обновление существующих тестов машин.
- **E2E** (CI-only): карточка машины показывает таблицу вооружений;
  `/encyclopedia/history` открывается, главы видны; кампания «Имперские
  войны» в «Хрониках войн».

### Границы (не делаем)

- ТТХ-дыры наёмников (0/7) и dead_fleet — вне справочника, не берём.
- Раздел «Персонажи» и lore-only отряды — не заводим.
- Дословный копипаст текстов книг — нельзя (авторские права).

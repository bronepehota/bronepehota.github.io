# Захват техники противника в бою — дизайн (#168)

**Дата:** 2026-07-05
**Issue:** [#168 — Захват техники противника в бою](https://github.com/Luxor/bronepehota/issues/168)
**Тип:** enhancement (боевая механика + UI)
**Scope:** «Захват боевых машин» (v0.3 §9) — приобрести захваченную машину в свою армию (Side A) + отметить свою машину захваченной с перезахватом (Side B). Single-army приложение: цель вводится вручную, армии противника нет.

## Контекст и правила (изучены)

**v0.3 §9 «Захват боевых машин»** (Tehnolog §9.1 / Star System §9 — идентичны):
- Боевая машина **без пилота** может быть захвачена: первый пехотинец, коснувшийся её, становится её новым пилотом; машина переходит к новому владельцу с **текущими прочностью и боезапасом**.
- Управлять машиной может только воин с рангом ≥ указанного в техлисте машины.

**Задача (дизайн-тяжёлая):** в приложении нет ни армии противника, ни добавления юнитов во время сессии (`GameSession` только обновляет существующие). Нужно смоделировать захват в single-army рамках.

### Текущее состояние кода
- `GameSession.setArmy({...army, units})` может добавлять юнитов — добавление mid-session технически доступно, UI нет.
- `PilotAssignmentModal` назначает солдата пилотом существующей машины (с проверкой ранга `strictPilotRankEnabled`); солдат помечается `isPilot`+`pilotOfInstanceId`, ход завершается.
- Боевой модал `ActionSelector` (выстрел/граната/ББ/ram) готов для нового действия.
- Каталог машин: `sources-registry`/`encyclopedia-registry` дают машины по фракциям.

## Решение

### Side A — Захват (приобрести машину)

**Точка входа:** в боевом модале солдата (`ActionSelector`) — новое действие **«Захват»** для солдат. Скрыто, если солдат уже пилот или каталог машин пуст. Выбор «Захват» → **закрывает боевой модал и открывает `CaptureModal`** (отдельный, как `PilotAssignmentModal`).

**`CaptureModal` — поток:**
1. **Выбор машины** — пикинг из **полного каталога** (все фракции/источники, агрегация через `sources-registry`/`encyclopedia-registry`).
   - **Фильтр фракции по умолчанию = противоположная** (не фракция игрока) — захваченная машина вражеская; игрок может переключить фракцию.
   - **Фильтр по рангу** (если `strictPilotRankEnabled`): только машины с `rank ≤ soldier.rank` (которые этот солдат может пилотировать).
   - Каждая карточка машины: имя, фракция, ранг, прочность_max, БК_max.
2. **Ввод текущего состояния** — игрок вводит **прочность** (1…прочность_max) и **боезапас** (0…БК_max) — узнав у соперника.
3. **Проверка ранга** — `soldier.rank ≥ machine.rank` (дублирующая защита; каталог уже отфильтрован, но проверить на confirm).
4. **Подтверждение** →
   - новый `ArmyUnit` (type=machine, data=machine из каталога, currentDurability/currentAmmo из ввода, уникальный `instanceNumber`/`instanceId`, `pilotInfo` = захватчик);
   - солдат-захватчик: `isPilot=true`, `pilotOfInstanceId`, ход завершён (как в `PilotAssignmentModal`);
   - `setArmy({...army, units: [...units, newMachine]})`.

**Расход действия:** захват — действие солдата в этом туре (солдат становится пилотом, больше не действует).

### Side B — Отметить захваченной (потеря + перезахват)

**Данные:** новое поле `ArmyUnit.isCaptured?: boolean` (машина).

**Карточка машины** (`MachineView`/`UnitCard`) при `isCaptured`:
- баннер-оверлей **«ЗАХВАЧЕНА ПРОТИВНИКОМ»** + машина гасится (`grayscale`/`opacity`);
- **все действия блокируются** — выстрел/ББ/таран/урон/ремонт/пилот-действия disabled;
- в **навигаторе юнитов** — пометка «захвачена».

**Toggle-кнопка** на карточке (внизу, рядом с боевыми кнопками):
- `isCaptured=false` → **«Отметить захваченной»**;
- `isCaptured=true` → **«Вернуть (перезахват)»**.

**Поведение:**
- Машина без пилота (по правилам захватывается только такая) → флаг просто помечает потерю; пилот не назначается.
- Перезахват (toggle off) → машина снова активна, **без пилота** — пилота назначает игрок через `PilotAssignmentModal`.
- Состояние сохраняется через `setArmy`.

### Типы и файлы
- `src/lib/types.ts` — `ArmyUnit.isCaptured?: boolean`.
- `src/lib/combat-types.ts` — `'capture'` в `CombatActionType`.
- `src/components/combat/ActionSelector.tsx` — кнопка «Захват» (gating: солдат, не пилот, каталог непустой).
- `src/components/modals/CaptureModal.tsx` (новый) — пикинг машины + ввод прочности/БК + проверка ранга + подтверждение.
- Каталог-хелпер — агрегация машин всех фракций (для пикинга); возможно в `encyclopedia-registry` или новом util.
- `src/components/cards/UnitCard.tsx` — перехват «Захват» → открытие `CaptureModal`; обработчик подтверждения (добавить машину + пилот); проброс `isCaptured`.
- `src/components/cards/unit-card/MachineView.tsx` — баннер «ЗАХВАЧЕНА» + toggle-кнопка + блокировка действий.

## Non-goals
- Захват орудий (артиллерии в приложении нет).
- Отслеживание позиции/контакта юнитов (single-army, вручную).
- Армия противника (не моделируется).
- Передача/хоп существующей машины между игроками в одной сессии.

## Краевые случаи
- `instanceNumber`/`instanceId` новой машины — уникальны (max+1 / uuid).
- Каталог пуст (custom-источник без машин) → «Захват» скрыт / в `CaptureModal` — «нет машин».
- Солдат уже пилот → «Захват» скрыт.
- Уничтоженная машина (прочность 0) → кнопку «отметить захваченной» disable.
- Side A и Side B независимы: добавление захваченной машины (Side A) не пересекается с флагом своей машины (Side B).

## Тесты
- **Unit:** агрегация каталога (cross-faction + фильтр ранга); генерация instanceNumber; обработка `isCaptured`.
- **E2E:** солдат → «Захват» → выбор машины + ввод прочности/БК → машина в армии с солдатом-пилотом (проверка ранга); Side B: «отметить захваченной» → баннер + блокировка → toggle «вернуть». Регрессия: pilot-assignment, боевые потоки зелёные.

## Критерии приёмки
- [ ] «Захват» солдата → `CaptureModal` (полный каталог, по умолчанию противоположная фракция, фильтр по рангу).
- [ ] Захват добавляет машину в армию с текущей прочностью/БК + солдат-захватчик становится пилотом (проверка ранга).
- [ ] Захваченная машина функционирует (действует следующим ходом).
- [ ] «Отметить захваченной» toggle → баннер + блокировка действий; перезахват (toggle).
- [ ] `npm run validate` + `npm run test:e2e` зелёные.

## Риски
- `ActionSelector` для 'capture' не должен идти в фазу PARAMETERS боевого модала (захват — не бросок) → перехват в `UnitCard`: при `'capture'` закрыть боевой модал и открыть `CaptureModal`.
- Агрегация каталога по всем фракциям/источникам — производительность/объём; пагинация/поиск не обязательны (машин немного).
- `isCaptured` — убедиться, что загрузка/сохранение армии (`army-storage`) сохраняет поле (новое опциональное поле — обратная совместимость ОК).

# Дизайн: турниры и рейтинг игроков («Бронепехота»)

**Дата:** 2026-10-30
**Статус:** одобрен пользователем (brainstorming; правка — десктоп равноправная цель для этого раздела)
**Ветка реализации:** `feat/tournaments-rating` (от `origin/main`)

## Контекст и запрос

Запрос от сообщества (Денис Шнайдер, Андрей Андреев, VK): вести статистику турнирных побед игроков. Прототип протокола — `Turnir.xlsx`: 8 игроков × 3 тура швейцарки, пары по столам, на каждого игрока за тур — победа (0/1), очки режима, очки армии; итоговые места 1–8; лист «Ростеры» — по 3 армлиста на игрока (~680–700 очков, фракции уже есть в приложении).

Пожелания (дословно из переписки):
- Рейтинг сортируется по **проценту побед**; при равном проценте — учитывать количество отыгранных партий.
- Подробная статистика: какие игры сыграны — режим, ростер, очки, турнир, армия, версия правил.
- Ачивки у имён: золотые/серебряные/бронзовые кубки за места, значки за участие в турнирах.
- На будущее: разбивка по регионам; спортивные дуэли с судьёй (пока только планы).
- Их вопросы: насколько сложно, что может слететь, не нагромождение ли, не лучше ли отдельный сайт.

## Принятые решения (brainstorming, 2026-10-30)

1. **Часть этого сайта**, не отдельный домен. Бэкенда нет — статический экспорт, обновление через merge PR → автодеплой. Нечему «слетать»: данные в git с историей.
2. **Обновление вручную** (владелец сайта) — из протокола организатора в JSON через PR; тот же поток, что импорт карточек.
3. **Игроки**: стабильный `id`-слаг + ник (виден всюду) + опциональные ФИО и ссылка на VK. Переименование ника не теряет историю.
4. **Ростеры**: фракция + очки + состав свободным текстом (как в протоколе). Жёсткая связь с юнитами энциклопедии — не делаем (составы неформальные, «Пираты Маркуса(стар.)(Т)*4»).
5. **Десктоп — равноправная цель** для этого раздела (правка владельца): рейтинговые таблицы и сетка туров проектируются от широкого экрана; мобила остаётся полностью рабочей (адаптив, не урезание).

## Цели / не-цели

**Цели v1:**
- Рейтинг всех игроков: игры, победы, %, сортировка по правилу Дениса.
- Страница турнира: места с кубками, матчи по турам, ростеры, правила/очки.
- Профиль игрока: ачивки, сводка, история матчей.
- Ачивки как производные данных: 🥇🥈🥉 за места 1–3, значок участия за турнир.
- Первый турнир — сид из `Turnir.xlsx`.

**Не-цели v1 (YAGNI):**
- UI-разбивка по регионам (поле в модели — да, фильтры — нет).
- Дуэли (модель допускает позже, UI/подсчёт — нет).
- Самообслуживание организаторов (формы, аккаунты, бэкенд).
- Связывание ростеров с юнитами приложения.
- Графики/диаграммы — только таблицы и списки.
- Публичное редактирование/регистрация игроков.

## Модель данных

### `src/data/tournaments/players.json`

```json
{
  "players": [
    {
      "id": "shnayder",
      "nick": "Шнайдер",
      "name": "Денис Шнайдер",
      "vkUrl": "https://vk.com/…",
      "region": null
    }
  ]
}
```

`name`, `vkUrl`, `region` — опциональны: поле может отсутствовать или быть `null`, оба случая читаются как «нет данных» (`region` — на будущее, не показывается в v1).

### Файл турнира `src/data/tournaments/<YYYY-MM-DD>-<slug>.json`

```json
{
  "id": "2026-10-<slug>",
  "name": "Название турнира",
  "date": "2026-10-11",
  "region": null,
  "rulesVersion": "community_star_system",
  "rosterPoints": 700,
  "format": "swiss",
  "organizers": ["Андрей Андреев"],
  "results": [
    { "place": 1, "playerId": "semen_kashapov" },
    { "place": 2, "playerId": "pavel_boev" }
  ],
  "matches": [
    {
      "round": 1, "table": 1,
      "playerId": "andrey_sukov", "opponentId": "pavel_boev",
      "win": false, "modePoints": 1, "armyPoints": 292
    }
  ],
  "rosters": [
    {
      "playerId": "shnayder", "round": null,
      "faction": "protectorate", "points": 700,
      "composition": "Спецназ Фелиция(Л), Родезия, …"
    }
  ]
}
```

Ключевые решения схемы:
- **Матчи хранятся построчно на игрока** (как в протоколе: строка = игрок × тур). Заведение турнира = транскрипция эксельки 1:1. Игра восстанавливается группировкой по `(round, table)`; `opponentId` обязателен при известном столе (ничья = обе строки `win:false`; `null`-соперник — техническая пропускная, в v1 не ожидается).
- `matches[].win: boolean` — единственный исход; очки режима/армии хранятся как в протоколе (пояснение к системе очков турнира — в вольном тексте на странице турнира не выводим, v1 это просто «очки тура»).
- `rosters[].round: number | null` — `null` = список армлистов на турнир без привязки к туру (протокол не всегда фиксирует, каким листом играли).
- `rulesVersion` — из существующего union (`'tehnolog' | 'community_star_system'`); валидация мягкая, в духе missions-registry (двойной каст, без рантайм-бросков).
- `faction` в ростерах — свободная строка протокола («ИМПЕРИЯ», «Волки», «МФ»), НЕ `FactionID`: словарь протоколов неформален, маппинг на фракции приложения не гарантирован.

## Логика рейтинга — `src/lib/rating.ts` (чистая функция + юнит-тесты)

Вход: `players.json` + список турниров. Выход — отсортированный рейтинг и ачивки:

- **games** = число строк `matches` игрока по всем турнирам; **wins** = строки с `win: true`.
- **winRate** = `wins / games` (точная дробь); игроки с 0 игр в рейтинг не попадают (профиль появляется с первой игры).
- **Сортировка**: winRate ↓ → при равенстве **больше игр выше** → ник (locale compare, ru) ↑ — детерминизм.
- **Отображение %**: один знак после запятой (`66,7%`); сортировка всегда по точной дроби, не по отображаемому значению.
- **Ачивки**: `gold/silver/bronze` — из `results` (места 1/2/3) по всем турнирам; **participations** = турниры, где игрок в составе (`players[]` турнира). Значки участия — список турниров (чипы с названием и годом) в профиле.

## Реестр — `src/lib/tournaments-registry.ts`

- `getAllPlayers(): Player[]`
- `getPlayer(id): Player | undefined`
- `getAllTournaments(): TournamentSummary[]` (отсортированы по дате ↓)
- `getTournament(id): Tournament | undefined`
- `getRating(): RatingRow[]` — делегирует `rating.ts`

Импорт JSON напрямую (`import data from '@/data/tournaments/…'`) — как sources/missions; статический экспорт, сборка на билде. Sitemap (`app/sitemap.ts`) дополняется: хаб + все турниры + все игроки.

## Страницы и маршруты (статический экспорт, `generateStaticParams`)

| Маршрут | Содержимое |
|---|---|
| `/tournaments` | Хаб: таблица рейтинга (место, ник + иконки кубков, турниры, игры, победы, %) + карточки турниров (название, дата, победитель, число участников) |
| `/tournaments/[id]` | Протокол: места с кубками; матчи по турам (десктоп — туры в ряд, как сетка СТОЛ 1–5 в эксельке; мобила — стек по турам); ростеры (фракция, очки, состав); шапка: дата, правила, очки, организатор |
| `/players/[id]` | Профиль: ачивки (кубки + чипы участия), сводка (игры/победы/%), история матчей (турнир → тур → соперник → результат → очки тура), ростеры игрока |

**Входы**: карточка на лендинге (рядом с «Хрониками войн») + тихая строка-телетайп в хабе энциклопедии (паттерн строки «// КАЛЬКУЛЯТОР БОЯ»). SEO: `BreadcrumbList` на детальных страницах (как у юнитов/миссий), sitemap/robots — автоматически из `app/sitemap.ts`.

**UI-язык**: досье/военной типографикой энциклопедии (Russo + IBM-mono, квадратные рамки, `// LABEL`-строки); акценты кубков — золотой/серебряный/бронзовый тона. **При реализации UI — навык `frontend-design`** (требование владельца). Тач-таргеты ≥44px там, где есть контролы.

## Тесты

**Юнит** (`src/__tests__/lib/`):
- `rating.test.ts`: пустые данные; один игрок; сортировка по winRate; тайбрейк «равный % → больше игр выше»; тайбрейк по нику; кубки из мест; участия; ничья считается игрой, но не победой; 0 игр → нет строки рейтинга; округление отображения.
- `tournaments-registry.test.ts`: загрузка, `getTournament`/`getPlayer` (hit + undefined), сортировка турниров по дате, целостность (уникальность мест, ссылки на известных игроков — мягкая проверка).

**E2E** (`e2e/tournaments.spec.ts`): хаб рендерит рейтинг в правильном порядке с кубками; страница турнира показывает места и матчи; профиль показывает историю; входы с лендинга ведут на хаб.

Обязательный чек-лист: `npm run type-check` + `npm run test` (+ e2e в CI; локально — паттерн переиспользования сервера :3001).

## Ответы на вопросы сообщества (для VK)

- **Сложность**: средняя; всё статическое — страницы собираются на билде.
- **Что может слететь**: ничего — нет сервера и БД; данные в git, каждое обновление = PR с историей.
- **Производительность**: статика, килобайты JSON; скорость GitHub Pages.
- **Обновление статистики**: протокол → JSON → merge; автодеплой за минуты.
- **Нагромождение**: раздел изолирован (`/tournaments`, `/players`), боевую утилиту не трогает.
- **Отдельный сайт**: не нужен; если позже понадобится самообслуживание организаторов — JSON-модель переедет без переделки (мы контролируем оба конца).

## Будущее (вне v1)

- Регионы: поле уже в модели; фильтры «регион / вся Россия» — когда появятся иногородние турниры.
- Дуэли: добавить второй источник игр (`context: 'tournament' | 'duel'`) — формула рейтинга не меняется.
- Расширение ачивок: серии побед, «лидер рейтинга месяца», значки за конкретные турниры-серии.

# Скролл списка целей гранаты — дизайн (#165)

**Дата:** 2026-06-30
**Issue:** [#165 — Скролл списка целей гранаты (видны только ~3)](https://github.com/Luxor/bronepehota/issues/165)
**Тип:** bug + UX-улучшение (mobile-first)
**Scope:** боевой модал, фаза результатов гранаты.

## Контекст

Из фидбека игрока (п.7): «При броске гранаты в окно помещается только 3 куба».
Уточнение: список проверок целей гранаты не скроллится — после ~3-й цели остальные
обрезаны/недоступны. Логика ограничений нет (`useCombatFlow.checkGrenadeTarget` /
`GRENADE_CHECK_TARGET` копят `grenadeBlastChecks[]` без лимита), значит проблема в вёрстке.

## Корневая причина

Контент-контейнер модала — flex-чайлд `flex-1 overflow-y-auto`
(`src/components/combat/BottomSheetCombatModal.tsx:243`) внутри flex-колонки
`max-h-[90vh] overflow-hidden flex flex-col` (`:157`) **без `min-h-0`**.

Без `min-h-0` у flex-чайлда `min-height` по умолчанию = `auto` (= высота контента),
поэтому он не сжимается ниже контента → внутреннее переполнение не возникает →
`overflow-y-auto` не показывает скролл → низ `CombatResults` срезается родительским
`overflow-hidden`. Классический flexbox-scrolling гитч.

**Почему только граната:** выстрел и ближний бой помещаются в один экран — переполнение
возникает только у безлимитного списка проверок (`CombatResults.tsx:392–470`).

`useBottomSheet` **не виноват**: тач-перехват включается лишь в верхней зоне 100px
(ручка), на контент скролл не давит.

## Цели

1. 6+ целей гранаты полностью видны/доступны при скролле.
2. Кнопка **ВЗРЫВ** всегда в зоне taps, сколько бы целей ни добавили.
3. Свежий результат (D20 vs броня) виден сразу после добавления — без ручного скролла.
4. Polish внутри сложившейся эстетики **Military Tech Blueprint** (`font-mono`,
   изумруд для гранаты, `combat-glass`, угловые акценты, soft-glow). Метафора —
   **arming panel / detonator** для sticky-блока.

## Non-goals

- `PilotTestModal.tsx` — тот же латентный flexbox-баг (`max-h-[90vh] overflow-hidden
  flex flex-col` → `flex-1 overflow-y-auto` без `min-h-0`), но не проявляется. Отдельная
  задача, **не чиним в рамках #165**.
- Полная переработка в **однострочные** компактные ряды (отвергнутый вариант 3).
  Сохраняем карточный вид; допускается лишь умеренное уплотнение (см. п.4.6).
- Лимит числа целей — правила не задают, YAGNI.

## Дизайн

### 1. Основной фикс — `min-h-0`

`BottomSheetCombatModal.tsx:243`:

```diff
- <div className="flex-1 overflow-y-auto custom-scrollbar p-2 md:p-3">
+ <div className="flex-1 min-h-0 overflow-y-auto custom-scrollbar p-2 md:p-3">
```

Безопасно для shot/melee: при коротком контенте переполнения нет → `min-h-0` нейтрален.
Этим чинится любой потенциальный overflow в модале, но проявляется только у гранаты.

### 2. Sticky «arming-панель» (только граната)

Блок «Проверить цель» (`CombatResults.tsx:472–535`) — stepper брони + кнопка **ВЗРЫВ** —
становится `sticky bottom-0`. Состав:

- **Live-талли** `💥 {hits}/{total} пробито` — счётчик попаданий по уже проверенным
  целям (польза за столом: счёт видно без скролла списка).
- **Stepper брони** (как сейчас).
- **Кнопка ВЗРЫВ** (как сейчас, `grenade-explode-button`).

Стиль: `bg-slate-800` (уже есть) + непрозрачный фон обязательно (контент не должен
просвечивать), верхняя граница цвета акции гранаты (изумруд) + угловые акценты в духе
модала. z-индекс выше списка.

**ПРИНЯТЬ** (`CombatResults.tsx:639–654`, общий для shot/melee/grenade) остаётся в
обычном потоке, под arming-панелью. Пока игрок добавляет цели — ВЗРЫВ приклеен; когда
закончил — скроллит вниз, панель «отлипает», ПРИНЯТЬ под ней. Решение подтверждено
пользователем (вариант F1).

### 3. Авто-скролл + pulse свежей проверки

Новые проверки дописываются **в конец** массива (`useCombatFlow.ts:147`), т.е. свежая
цель оказывается внизу списка — прямо над arming-панелью, уже в зоне видимости. Поэтому
авто-скролл нужен лишь когда игрок отскроллил вверх смотреть историю:

- `useRef` на последнюю проверку + эффект на рост `result.grenadeBlastChecks.length` →
  `scrollIntoView({ block: 'nearest' })`, чтобы свежий результат точно был виден над
  arming-панелью.
- Свежая проверка получает краткое изумрудное кольцо-пульс (поверх существующего
  `animate-pop-in`), куда падает взгляд.

### 4. Polish-слой (frontend-design harvest, всё принято)

Мелкие штрихи в той же эстетике. Если при реализации scope начнёт расти — пункты 4.1,
4.2 и 4.6 первые кандидаты на отсечение (core = п.1–3).

**4.1. Empty-state.** Пока `grenadeBlastChecks` пуст, над arming-панелью — тонкая
подсказка с иконкой бомбы («Цели не проверены…»), мелким шрифтом.

**4.2. Danger-тинт.** Если бросок дистанции = 1 (свой боец в зоне взрыва,
`CombatResults.tsx:297`) — верхняя граница arming-панели пульсирует красным вместо
изумруда.

**4.3. Метки «ЦЕЛЬ N» на каждой проверке.** Сейчас у карточки нет идентификатора
(`key={idx}` не отображается) — игроку сложно сопоставить результат с конкретной моделью
на столе. Компактный тег `Ц-1, Ц-2…` (по индексу в `grenadeBlastChecks`) решает это и
делает live-талли осмысленным.

**4.4. Скролл-fade (подсказка края).** Полупрозрачный градиент на верхнем краю области
списка, когда над текущим вьюпортом есть контент (`scrollTop > 0`). Прямо бьёт по корню
жалобы: игрок видит «тут ещё есть, можно скроллить». Реализация — `pointer-events-none`
оверлей или `mask-image` на скролл-контейнере; показ управляется состоянием скролла.

**4.5. Микро-фидбек детонации.** У свежей ПРОБИТО-карточки — короткая вспышка границы
(emerald flare) в момент разрешения; на тапе **ВЗРЫВ** — `navigator.vibrate()` (короткое
вибро-«взрыв» в ладони). On-theme, progressive enhancement: на iOS Safari `vibrate`
недоступен — просто молча пропускаем (feature-detect).

**4.6. Умеренное уплотнение карточек.** `p-4`→`p-3` и чуть мельче кубик в карточке
проверки, чтобы 2–3 цели влезали над arming-панелью без скролла. **Не** однострочные
ряды — карточный вид и сетка «D20 | броня» сохраняются.

## Риски / заметки

- `sticky bottom-0` внутри скролл-контейнера требует **непрозрачного фона** у панели —
  иначе контент списка просвечивает. Проверить визуально (Playwright screenshot) на
  тёмном фоне.
- `min-h-0` глобально на модале — проверить, что shot/melee/handler-фазы не получили
  неожиданный скролл/сжатие (там контент короткий, ожидается нейтральность).
- Авто-`scrollIntoView` не должен конфликтовать со sticky-панелью: свежая проверка
  должна оказываться над панелью, а не под ней (`block: 'nearest'` + при необходимости
  `scroll-padding-bottom`).
- `navigator.vibrate` — feature-detect (`typeof navigator.vibrate === 'function'`);
  отсутствие (iOS Safari) не должно ломать тап.
- Scroll-fade не должен перекрывать таргеты (overlay → `pointer-events: none`).

# Discoverability боя: мосты «энциклопедия → игра» и ясность первого экрана

Дата: 2026-08-26
Статус: утверждён (подход B)
Ветка: `feat/battle-discoverability`

## Контекст и проблема

Данные аналитики показывают: трафик есть на лендинге и страницах энциклопедии (SEO
работает — sitemap, JSON-LD), но в приложение (`/app` — построитель армии и бой)
почти никто не доходит. `battle_start` ≈ 0.

### Расхождения GA4 ↔ Яндекс.Метрика

Две независимые причины, обе вне кода приложения:

1. **Ручной пост-деплой чек-лист GA4/Метрики не выполнен** (после PR #223) —
   в GA4 включён Enhanced measurement «Page views», который **двоит просмотры**
   поверх нашего `RouteTracker`; параметры воронки не зарегистрированы как
   custom dimensions; `battle_start`/`battle_engaged` не помечены как конверсии.
   → Инструкция заведена отдельным issue:
   **[bronepehota.github.io#225](https://github.com/bronepehota/bronepehota.github.io/issues/225)**.
2. Для РФ-аудитории **GA ≤ Метрика — норма** (блокировщики режут GA сильнее).
   Сверять события, не сессии.

Код аналитики (`src/lib/analytics.ts`, `RouteTracker`) корректен и не меняется.

### UX-разрывы воронки (подтверждено кодом)

| Переход | Состояние | Проблема |
|---|---|---|
| Лендинг → приложение | CTA «ПЕРЕЙТИ В ШТАБ» в гером | Слово «штаб» — жаргон; не говорит, что тут есть бой |
| Лендинг → энциклопедия | Только ссылки в футере (дно) | Низ лендинга не читают; `FactionsSection` — декор без ссылок |
| Энциклопедия → бой | «← В приложение» (11px, `rust/60`) | На `UnitDetailPage` CTA в игру **нет вообще** |
| После входа в /app | 6-шаговый визард | Трение до первой ценности (в этом дизайне НЕ упрощается) |

## Решение — подход B: «мосты + ясность»

Эстетика не меняется: military-HUD (Russo One, IBM Mono, rust/amber/sand,
угловые скобки, зерно). Меняется информационная архитектура.

### 1. Первый экран лендинга

Заменяем пару разрозненных кнопок («ПЕРЕЙТИ В ШТАБ» + «КАЛЬКУЛЯТОР»)
на модульную строку-консоль с микротекстами:

```
┏━━━━━━━━━━━━━━━━━━━━━━━━━┓
┃ ▸ ШТАБ                  ┃   primary: акцент-rust, угловые скобки,
┃   собери армию и веди бой → ┃   крупнее; href=/app
┗━━━━━━━━━━━━━━━━━━━━━━━━━┛
┌─ ЭНЦИКЛОПЕДИЯ ────────┐ ┌─ КАЛЬКУЛЯТОР ───────┐
│   отряды, лор, тактика │ │   броски и урон в бою │   secondary, steel
└───────────────────────┘ └─────────────────────┘
```

- Mobile: ШТАБ — широкая primary-панель; вторичные модули в столбец.
  Desktop (md+): три в ряд, ШТАБ выделен.
- Tap-таргеты ≥ 44px (WCAG 2.5.5, mobile-first).
- Анимации: существующий staggered reveal (`showText`/`showCTA`) расширяется
  на модули delay-каскадом. Новых анимационных сущностей нет.
- **Промо-цитата в гером остаётся целиком, без сжатия** (решение владельца).
  Заголовок, подтвет, кредит Технолога — без изменений.
- Battle-state (карточка «Бой идёт / Продолжить / Начать заново / Калькулятор»)
  остаётся без изменений — возвращающегося игрока не трогаем.
  Модульная строка показывается **только в свежем состоянии** (нет активного боя
  в `bronepehota_army`); логика переключения состояний `CTAButton` — как сейчас.
- `FactionsSection.tsx`: карточки фракций оборачиваются в `Link` →
  `/encyclopedia/factions` (+ hover-подсветка). Декор становится навигацией.

### 2. Мосты «энциклопедия → бой»

**`UnitDetailPage.tsx`** — в конец досье добавляется панель призыва:

```
// В БОЙ
[ ВЗЯТЬ ОТРЯД В БОЙ → ]     ← кнопка в цветах фракции (getFactionColors)
```

- Ссылка: `/app?faction=<faction юнита>`.
- Только на странице; в `UnitDetailSheet` (модалка внутри боя) CTA не добавляем —
  там игрок уже в приложении.
- Тексты досье не меняются; панель — новый элемент.

**`FactionsListPage.tsx`** — на карточке фракции компактная ссылка
«Собрать армию →» → `/app?faction=<id>`. «← В приложение» в шапке остаётся.

### 3. Deep-link `/app?faction=<id>`

Механика в `src/app/app/page.tsx`:

- На mount, **после** `loadArmy()`, читаем `window.location.search`.
  Без `useSearchParams` — не нужен Suspense в static export.
- Чистая функция-хелпер (юнит-тестируемая):

  ```ts
  parseFactionParam(search: string, validFactions: string[]): string | null
  ```

- Фракция валидируется по фракциям **текущего источника** (`sources-registry`).
  Невалидная — молча игнорируется.
- Применяется **только к свежей армии**: `units.length === 0 && !isInBattle`.
  Армию вернувшегося игрока не перезаписываем.
- После применения параметр удаляется из URL (`history.replaceState`) —
  перезагрузка страницы не переустанавливает фракцию.
- Шаги визарда НЕ пропускаются: фракция лишь предвыбрана на своём шаге.
  (Пропуск визарда / «быстрый старт» — подход C, out of scope.)

### 4. Аналитика: событие `battle_entry`

```ts
trackEvent('battle_entry', {
  from: 'landing_hero' | 'landing_factions'
      | 'encyclopedia_unit' | 'encyclopedia_factions'
})
```

- Шлётся при клике на каждый новый CTA; фасад доставит в GA4 и Метрику,
  офлайн-буфер включён автоматически.
- Полная измеримая воронка:
  `battle_entry` → `wizard_step` (1–6) → `battle_start` → `battle_engaged`.
- Параметр `from` регистрируется как custom dimension в GA4 —
  дополнить issue #225 строкой в таблицу dimensions.

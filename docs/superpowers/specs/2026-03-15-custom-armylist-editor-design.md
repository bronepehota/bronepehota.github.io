# Спецификация: Редактор пользовательских армлистов

**Дата:** 2026-03-15
**Статус:** На утверждении
**Автор:** Claude

---

## Контекст

Пользователи хотят создавать собственные армлисты для игры Бронепехота: балансировать юнитов, добавлять новые фракции и делиться своими наборами с сообществом. Сейчас все источники захардкожены в `sources-registry.ts` и требуют изменений в коде проекта.

**Проблема:** Нет возможности создавать кастомные армлисты без участия разработчиков.

**Решение:** Отдельное приложение-редактор по адресу `/editor` с хранением данных в localStorage и возможностью экспорта для публикации.

---

## Ключевые решения

| Решение | Выбор | Обоснование |
|---------|-------|-------------|
| Модель расширения | Гибридная | Можно создать источник с нуля ИЛИ на основе существующего |
| Изображения | URL + превью | Пользователь указывает URL, изображение загружается везде |
| Layout редактора | Сайдбар (3 колонки) | Классический десктопный UI: Источники → Фракции → Юниты |
| Интеграция с /app | Раздел "Мои источники" | Пользовательские источники отдельно от встроенных |
| Импорт/Экспорт | JSON + QR-код | Файлы для офлайн + QR для мобильного шаринга |
| Валидация | Стандартная + подсказки | Предупреждения о проблемах, но можно сохранить |
| Хранение | localStorage + abstraction | Обёртка для будущего перехода на Firestore |

### Модель данных

```typescript
interface CustomSource {
  id: string;                    // Уникальный ID источника
  name: string;                  // Название (ru)
  description: string;           // Описание
  version: string;               // Версия (1.0 по умолчанию)
  baseSource: SourceID | null;   // Базовый источник для расширения (null = с нуля)
  factions: Faction[];           // Фракции
  squads: Squad[];               // Отряды
  machines: Machine[];           // Техника
  createdAt: string;             // ISO дата создания
  updatedAt: string;             // ISO дата обновления
}
```

### Storage Abstraction

```typescript
// src/lib/editor/storage.ts
interface CustomSourcesStorage {
  getAll(): CustomSource[];
  getById(id: string): CustomSource | null;
  save(source: CustomSource): void;
  delete(id: string): void;
  exportToJson(source: CustomSource): string;
  importFromJson(json: string): CustomSource;
}

// Текущая реализация: localStorage
// Будущее: Firestore adapter
```

### Интеграция с sources-registry

```typescript
// src/lib/sources-registry.ts
// Добавить функцию:
function getAllSourcesWithCustom(): SourceData[] {
  const builtIn = getAllSources();
  const custom = customSourcesStorage.getAll().map(convertToSourceData);
  return [...builtIn, ...custom];
}
```

### Переопределение юнитов

При расширении источника (`baseSource` не null):
- Юнит с новым ID → **добавляется** к фракции
- Юнит с существующим ID → **переопределяет** оригинал
- Фракция с новым ID → **добавляется** к источнику

## Валидация данных

### Обязательные поля

**Отряд (Squad):**
- `id` — уникальный идентификатор
- `name` — название на русском
- `faction` — ID фракции
- `cost` — стоимость (число > 0)
- `soldiers` — массив 1-6 солдат

**Солдат (Soldier):**
- `rank` — ранг (0-7)
- `speed` — скорость (1-6)
- `range` — дальность (dice notation или "")
- `power` — сила (dice notation или "")
- `melee` — ближний бой (0-7)
- `armor` — броня (1-6)

**Техника (Machine):**
- `id`, `name`, `faction`, `cost` — как у отряда
- `rank` — ранг техники (1-5)
- `fire_rate` — скорострельность
- `ammo_max` — запас боеприпасов
- `durability_max` — максимальная прочность
- `weapons` — массив оружия
- `speed_sectors` — секторы скорости (должны покрывать 1..durability_max)

### Dice Notation

Допустимые форматы для `range` и `power`:
- `D6`, `D12`, `D20`
- `D6+2`, `D12-1`
- `2D6`, `2D12`
- `ББ` — только для melee
- `""` — пусто (нет стрельбы/ближнего боя)

### Предупреждения (не блокируют сохранение)

- Некорректный dice notation (например, `2D` вместо `2D6`)
- Gap в speed_sectors
- Отряд без солдат
- Дублирующийся ID юнита
- URL изображения не начинается с `http`

### sources-registry.ts

```typescript
export function getSourceWithCustom(sourceId: string): SourceData | null {
  // Сначала проверяем встроенные
  if (sourcesRegistry[sourceId]) {
    return sourcesRegistry[sourceId];
  }

  // Затем пользовательские
  const customSource = customSourcesStorage.getById(sourceId);
  if (customSource) {
    return convertToSourceData(customSource);
  }

  return null;
}

export function getAllSourcesWithCustom(): ArmyListSource[] {
  const builtIn = getAllSources();
  const custom = customSourcesStorage.getAll().map(s => ({
    id: s.id,
    name: s.name,
    description: s.description,
    version: s.version,
  }));
  return [...builtIn, ...custom];
}
```

## Открытые вопросы

1. **Максимальный размер localStorage?** — Браузеры ограничивают ~5-10 МБ. Для JSON данных этого достаточно, но Base64 изображения могут быстро заполнить лимит. Решение: не хранить изображения, только URL.

2. **Версионирование источников?** — При обновлении базового источника (Star System) пользовательские переопределения могут сломаться. Решение: хранить версию базового источника и предупреждать о несовпадении.

3. **Дубликаты при импорте?** — Что делать если импортируется источник с ID, который уже существует? Решение: показать диалог "Заменить / Импортировать как копию".

Редактор армлистов — отдельное десктопное приложение по `/editor` с:
- Гибридной моделью источников (с нуля или на основе существующего)
- 3-колоночным сайдбаром для навигации
- Превью карточек как в основном приложении
- Экспортом в JSON и QR-код
- Интеграцией с основным приложением через раздел "Мои источники"
- Абстракцией хранения для будущего Firestore

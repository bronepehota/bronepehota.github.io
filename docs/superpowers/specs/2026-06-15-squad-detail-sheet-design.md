# Squad Detail Sheet — Lean stats-first карточка деталей отряда

- **Дата:** 2026-06-15
- **Статус:** Approved (дизайн согласован)
- **Ветка:** `squad-detail-sheet`
- **Связано:** PR #149 (Tehnolog source) — фича разрабатывается поверх него, т.к. опирается на поддержку нескольких источников.

## Контекст и проблема

В режиме сборки армии тап по отряду открывает `EncyclopediaModal`. Сейчас он:

1. **Автопрокрутка к фото** — `UnitSelector.tsx:538` передаёт `scrollTarget: 'soldier-images'`, поэтому шторка открывается на изображениях, а не на статах.
2. **Статы не видны** — блок `DATA_STATS` в модалке показывает только стоимость/фракцию/тип/ID; по-солдатская таблица статов (А/Ск/Дальн/Мощн/ББ/Св/Бр) отсутствует как отдельная секция (значения рассыпаны под миниатюрами ниже).
3. **Хардкод источника** — `UnitSelector.tsx:533` собирает `sources: [{ id: 'star_system', cost }]`, игнорируя реально выбранный источник и новую реальность нескольких источников (Star System + Технолог).

Игрок не может увидеть статы, по которым принимает решение о добавлении отряда.

## Решённые развилки (brainstorming)

1. **Форма:** переделать текущий bottom-sheet (а не новый экран / не инлайн-раскрытие). Остаться в потоке сборки армии.
2. **Источник:** бейдж выбранного источника («Статы из: Технолог»), отражающий реально выбранный источник. Переключатель/сравнение источников не делаем — большинство отрядов живут в одном источнике.
3. **Глубина:** lean — таблица статов + бейдж/стоимость + 1 строка лора + кнопка «Добавить». Полный лор/история/галерея остаются в `/encyclopedia`.

## Ключевое ограничение области

`EncyclopediaModal` используется в **трёх** местах: `UnitSelector` (сборка армии), `UnitCard` (игровой режим), `UnitCard.legacy`. Чтобы не регрессить игровой режим (там `UnitCard` уже показывает статы, а модалка даёт лор/галерею), **создаём новый компонент для сборки армии**; `EncyclopediaModal` в игровом режиме не трогаем.

## Архитектура и компоненты

### NEW `UnitDetailSheet`
`src/components/encyclopedia/UnitDetailSheet.tsx` — lean bottom-sheet:

```
┌─ header ─ фракция·имя ─ [Технолог]·стоимость ─ ✕
│ ─────────────────────────
│ UnitStatTable              ← статы сразу, без прокрутки
│ ─────────────────────────
│ «Лор одной строкой…»       (только если есть лор)
│ ─────────────────────────
│ [＋ Добавить в армию]      (рендерится при переданном onAdd)
│ Открыть в энциклопедии →   (ссылка на /encyclopedia)
└─
```

- Переиспользует `useBottomSheet` (свайп-вниз для закрытия).
- Принимает: `unit` (Squad|Machine + `type`), `sourceId`, `onAdd?`, `onClose`, `isOpen`.

### NEW `UnitStatTable`
`src/components/encyclopedia/UnitDetail/UnitStatTable.tsx` — переиспользуемая таблица статов.

- **Отряды** — по строке на солдата:

  | № | А | Ск | Дальн | Мощн | ББ | Св | Бр |
  |---|---|---|---|---|---|---|---|

  - А=ранг, Ск=скорость, Дальн=range, Мощн=power, ББ=melee, Св=свойство/модификатор, Бр=armor.
  - Пустые `range`/`power` → «—». Нотация кубиков как есть (`D6`, `2D6-1`, `ББ`).
  - **Св:** `Пр3/Пр4/Пр5` → компактный бейдж; нет свойства → «—».
  - На узких экранах (<360px) — горизонтальный скролл таблицы; иначе умещается.

- **Машины** — компактный блок (не 7-колоночная таблица): Ранг · Скорость(сектора) · Прочность · Б/с · Боезапас · Вооружение (список: название, дальность, мощь).

- Убрать хардкод `sources: [{ id: 'star_system' }]` (стр. 533) и `scrollTarget` (стр. 538).

- Передать `onAdd` (для отрядов — `onAddUnit(squad)`; для машин — `onAddMachine` с последующим выбором вооружения).

### MODIFY `ArmyBuilder.tsx`

### Без изменений

- `src/components/cards/UnitCard.tsx`, `UnitCard.legacy.tsx`.

## Бейдж источника и поток данных

```
ArmyBuilder (selectedSource, str. 82)
   └─ sourceId prop ─→ UnitSelector ─→ UnitDetailSheet
                                           └─ getSource(sourceId).name → «Статы из: Технолог»
```

Статы — из `selectedUnit.data` (фильтруются по выбранному источнику в `ArmyBuilder`/`getSourceWithCustom`). Если отряд присутствует в нескольких источниках — бейдж корректен для текущего; переключатель источников сознательно не делаем.

## Кнопка «Добавить» и связь с /encyclopedia

- «Добавить в армию» вызывает тот же обработчик, что и карточка отряда: `onAddUnit(squad)` для отрядов; для машин — существующий поток добавления машины (с выбором вооружения), затем закрывает шторку.
- Из шторки — ссылка «Открыть в энциклопедии» на `/encyclopedia` для полного лора/галереи.

## Доступность и мобильность

- Bottom-sheet со swipe-down (существующий паттерн).
- Таблица статов читаема на 320px; при необходимости горизонтальный скролл.
- Тач-таргеты ≥44px для «Добавить» и ✕.
- `aria-label` для иконок/кнопок.

## Тестирование

- **Unit `UnitStatTable`**: корректные строки для отряда с разными солдатами; пустые значения («—»); модификаторы (Пр3/Пр4/Пр5); нотация кубиков (`2D6-1`); вариант машины (ранг/прочность/вооружение).
- **Unit `UnitDetailSheet`**: бейдж источника показывает имя выбранного источника (через мок `getSource`); «Добавить» вызывает колбэк с правильным юнитом; лор/ссылка рендерятся при наличии.
- **E2E** (`e2e/army-creation.spec.ts`, новый тест): выбор источника Технолог → тап по отряду → шторка открыта, `UnitStatTable` виден сверху (не прокручен к фото) → бейдж источника = «Технолог» → «Добавить» добавляет отряд в армию (счётчик армии растёт).
- `npm run type-check`, `npm run test` — зелёные; существующий игровой `EncyclopediaModal` и его E2E не регрессят.

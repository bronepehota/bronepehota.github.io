# Миссия «Захват и удержание точек» (классический сценарий)

**Дата:** 2026-06-22
**Автор:** brainstorming-сессия
**Статус:** одобрен пользователем

> **Ревизия после реализации (коммит `75acd9b`):** по запросу пользователя верхний баннер лимита ходов **убран**. Вместо этого число туров миссии показывается прямо в попапе «ЗАВЕРШИТЬ ТУР» — заголовок вида «ЗАВЕРШИТЬ ТУР 3 ИЗ 6?» (для миссий без `turnCount`/свободной игры — без «ИЗ N»). Раздел «Баннер лимита ходов (GameSession.tsx)» ниже и все упоминания верхнего баннера в тексте спецификации считаются **устаревшими**. Чистая функция `isTurnLimitReached`, добавленная под баннер, удалена как неиспользуемая (остались `missionHasParticipantsForFaction` и `missionHasAnyParticipants`).

## Контекст и проблема

В системе миссий (`src/data/missions/`) сейчас 6 нарративных сценариев кампании «Цербер». Все они:

- **асимметричные** (у каждой стороны своя цель);
- **привязаны к фракциям** (только Полярис vs Протекторат);
- **с предписанным составом** (`participants`) → выбор миссии авто-собирает армию и **пропускает шаг бюджета** (`ArmyBuilder.tsx:298-311`);
- дословный канон из официальных PDF Tehnolog.

Не хватает классического для множества варгеймов **симметричного** сценария — «захват и удержание точек» (control points). Сообщество [«Технолог | Варгеймы»](https://m.vk.com/tehnologwargames) прямо содержит такие сценарии («Захват 2/3/5 точек»). Такой сценарий по своей природе **другой**: обе стороны с одинаковой целью, без фиксированных фракций и без предписанного состава — армии набираются под бюджет.

Проблема: текущая схема и визард заточены под асимметрию + авто-сбор. Прямое добавление сценария без `participants` сломает маршрут визарда (`buildMissionArmy` вернёт пустую армию с `pointBudget: 0`).

## Цель

Добавить **одну параметризованную карточку** «Захват и удержание точек» как классический симметричный сценарий: обе стороны набирают армии под бюджет и сражаются за маркеры-точки. Сценарий остаётся **информационной справкой** (как 6 существующих) — без живого подсчёта очков, без отслеживания состояния. Исключение — лёгкий пассивный баннер о достижении лимита ходов в бою.

## Ключевые решения (из brainstorming)

1. **Справка, а не трекер.** Приложение не считает очки контроля и не объявляет победителя — игроки делают это вживую. (Альтернатива «живой трекер точек» отвергнута — ломает философию «без отслеживания».)
2. **Без предписанных сил → бюджет.** У миссии нет `participants`; визард идёт путём свободной игры: шаг бюджета сохраняется, армия собирается вручную.
3. **Одна параметризованная карточка.** Число точек (2/3/5) — параметр внутри описания, не три отдельных карточки.
4. **Лимит ходов: справка + пассивный баннер.** `turnCount` показан в параметрах; при достижении лимита в бою появляется неблокирующий dismissible-баннер.
5. **Размещение: общий кластер со свободной игрой.** В визарде карточка рендерится сразу под свободной игрой без делителя (они схожи — обе «свои армии под бюджет»); в энциклопедии — под заголовком кампании.
6. **Подход A (переиспользование схемы + конвенции).** Без расширения типов; симметрия — дублированием текста цели; сигнал `participants` — единый источник правды для маршрута и кластеризации.
7. **Обобщённые классические правила.** Текст пишется по стандартным варгейм-конвенциям (не дословная цитата VK); `sourceUrl` → на сообщество.

## Маршрут сборки (ArmyBuilder.tsx)

Блок `onConfirm` шага миссии (~295-315): перед авто-сбором проверяем наличие предписанных сил для выбранной фракции.

```js
if (mission) {
  const hasForces = missionHasParticipantsForFaction(mission, faction);
  if (hasForces) {
    const built = buildMissionArmy(mission, faction, typedSquads, typedMachines);
    setArmy({ ...army, units: built.units, totalCost: built.totalCost,
              pointBudget: built.totalCost, currentStep: 'unit-select' });
    setSetupStep('units');
    return;            // 6 нарративных — как раньше
  }
  // участников нет → проваливаемся в бюджет
}
setSetupStep('budget');  // «Захват точек» и свободная игра — ручная сборка
```

Сигнал `participants` — единый источник правды: он же кластеризует селектор, он же направляет визард (DRY).

## Кластеризация в селекторе (MissionSelector.tsx)

Реальные миссии делятся на два потока:
- **Без участников** (`missionHasAnyParticipants(m) === false`) → рендерятся в общем блоке `space-y-2` сразу под карточкой свободной игры, **без янтарного делителя**.
- **С участниками** → существующая группировка по кампаниям (`groups`) — «Цербер» ниже.

Раскладка (одобрена пользователем):

```
───── МИССИЯ ─────

🧭  Свободная игра
    Без сценария

🎯  Захват и удержание точек
    Симметричный сценарий…

─── КАМПАНИЯ «ЦЕРБЕР» ───

🎯  Освобождение
   … (6 миссий)
```

**Важно:** кластеризация применяется **только в визарде**. В **энциклопедии** (`MissionListPage`, `/encyclopedia/missions`) миссия показывается под заголовком кампании «Классические сценарии» (группировка по канону). Wizard группирует по поведению сборки, энциклопедия — по теме. Это сознательное разделение контекстов.

## Баннер лимита ходов (GameSession.tsx)

Рядом со ссылкой на миссию (~1068, `game-session-mission-link`):
- **Условие:** `selectedMission?.parameters.turnCount` существует **и** `(army.currentTurn || 1) >= turnCount`.
- Неблокирующий, dismissible (локальный стейт `turnLimitDismissed`; сбрасывается при смене миссии).
- **Текст:** «⏱ Достигнут лимит ходов миссии (N). Подсчитайте очки контроля и определите победителя.»
- Естественно не появляется для свободной игры и «Капкана» (нет `turnCount`) — гарантируется условием.

## Хелперы (missions-registry.ts)

Чистые функции — единый источник правды для визарда и селектора, и unit-тестируемые:

```ts
/** Есть ли предписанные силы для данной фракции (маршрут визарда). */
export function missionHasParticipantsForFaction(m: Mission, faction: FactionID): boolean {
  return (m.participants?.[faction]?.length ?? 0) > 0;
}

/** Есть ли предписанные силы вообще (кластеризация селектора). */
export function missionHasAnyParticipants(m: Mission): boolean {
  return !!m.participants && Object.values(m.participants).some(a => !!a && a.length > 0);
}
```

## Контент и диаграмма

- **Правила** — обобщённая классическая формулировка по стандартным варгейм-конвенциям (см. JSON выше). Не дословная цитата VK.
- **Диаграмма** `public/images/missions/zahvat_tochek/diagram.png` — чистая схема (SVG → PNG, в фирменных цветах slate/amber): стол 120×80, маркеры точек в представительной раскладке на 3 точки (центр + два фланга), зоны развёртывания у противоположных коротких краёв, легенда. Варианты на 2 и 5 точек описаны текстом в `setup`. Генератор-скрипт коммитится в репо.
- **sourceUrl** → `https://m.vk.com/tehnologwargames`.

## Тестирование

- Кампания `'classic'` присутствует в `getAllCampaigns()`; `getCampaign('classic')` возвращает её.

**Хелперы** (отдельный unit-тест): `missionHasParticipantsForFaction` и `missionHasAnyParticipants` возвращают `false` для `zahvat_tochek`, `true` для `osvobozhdenie`+`protectorate`.

**E2E** (`e2e/missions.spec.ts` + `e2e/helpers/setup.ts`):
- Выбор «Захват и удержание точек» в визарде → шаг **бюджета** (виден ввод бюджета), не авто-сбор.
- Карточка в кластере свободной игры: делитель «КАМПАНИЯ «ЦЕРБЕР»» НЕ встречается между свободной игрой и этой карточкой.
- Энциклопедия: `/encyclopedia/missions` показывает миссию под «Классические сценарии»; `/encyclopedia/mission/zahvat_tochek` рендерит цели, правила, диаграмму.
- `GameSession`: открыть попап «ЗАВЕРШИТЬ ТУР» → заголовок содержит число туров миссии (напр. «ИЗ 6»).

## Обработка граничных случаев

- Миссия без `participants` → корректный провал в бюджет (не пустой авто-сбор).
- Для миссий без `turnCount` (свободная игра, «Капкан») суффикс «ИЗ N» в попапе «ЗАВЕРШИТЬ ТУР» не показывается.
- `currentTurn` может быть `undefined` → fallback `|| 1`.
- `diagramImage` опционален — рендер должен работать, пока ассет не добавлен (но в финале ассет обязателен).

## Не входит в скоуп (явно)

- Трекер очков контроля, учёт «кто держит точку», определение победителя приложением.
- Блокировка перехода хода после лимита.
- Включение наёмников в цели (можно добавить позже).
- Множественные диаграммы под варианты 2/5 точек.

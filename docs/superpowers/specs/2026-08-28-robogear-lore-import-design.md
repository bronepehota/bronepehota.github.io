# Импорт лора с robogear.ru — главы, секции, рассказы и поиск по «Робогир»

Дата: 2026-08-28. Ветка: `feat/robogear-lore-import`.

## Контекст и цель

Официальный сайт вселенной Робогир ([robogear.ru](http://www.robogear.ru/), ООО
«Технолог», архив ~2007–2009) содержит канонический лор, которого нет в нашей
энциклопедии. Вселенная общая с Бронепехотой: фракция Протекторат и техника
(Salamander, Raptor, Varan…) — те же. Цели:

1. Дополнить `/encyclopedia/history` официальной хроникой (продолжение после
   4530 г.), справочными секциями вселенной и рассказами игроков.
2. Сделать приложение и сайт находимыми по запросам «Робогир» / «Robogear»
   (SEO + внутриприложеческий поиск).

Существующий пайплайн импорта внешнего лора (романы, справочник техники,
«Летопись: Звёздные герои») переиспользуется как есть — см.
`docs/ENCYCLOPEDIA_LORE_SOURCES.md`.

## Решения (сводка, согласовано с владельцем 2026-08-28)

| Вопрос | Решение |
|---|---|
| Скоуп контента | Официальный канон: «Новейшая история Империи» + справочные секции Star Heroes + «Легенды мира Робогир» (сверка дублей). Рассказы игроков — **да, с атрибуцией** (решение изменено в ходе брейншторма: изначально «не трогаем», затем «берём с указанием источников»). Истории героев Star Heroes — вне скоупа. |
| Размещение | Всё внутри `/encyclopedia/history`: хроника — главы 9–11, справочные секции и рассказы — группы в оглавлении. Новых роутов/табов нет. |

| Поиск | Оба: SEO (кириллические ключи + тексты) и расширение поиска в приложении. |
| Реестр источников | Обновляется `docs/ENCYCLOPEDIA_LORE_SOURCES.md` с инвентаризацией секций по статусам. |

## Дизайн

### 1. Контент-модель и размещение

Всё — `src/content/history/*.md` (лоадер `src/lib/history.ts`, страница
`src/app/encyclopedia/history/page.tsx`). Новых роутов и табов не появляется.

**Хроника — главы 9–11** (после «Двух сил» order 7; «Пехота Доминиона»
order 8 не двигается):

| Глава | order | era | Источник |
|---|---|---|---|
| «Конверсия, Раскол, Регентство» | 9 | уточняется по тексту (~4530+) | `legend_empire.pdf` |
| «Флот эпохи Регентства» | 10 | — | `legend_empire.pdf` |
| «Легендарные Имперские Лорды» | 11 | — | `legend_empire.pdf`; 6 лордов (Долгорукий, Кросс, Эркхарт, Агата, Шинджи, Маркус Трёхглазый) подразделами одной главы |

**«Легенды мира Робогир» — источник дедупликации, не новые главы.** Уникальные
эпизоды, отсутствующие в главах 1–7 (кандидаты: «Битва за Блауд», «Арсеналы
Протектората», «Восстание»), либо дозаполняют существующие главы, либо
становятся отдельной главой — решение по факту чтения, фиксируется в реестре.

**Справочные секции Star Heroes** — группы `group: Справочник` без `era`:
«Космография Доминиона», «Политическое устройство: Протекторат и Империя»,
«Сравнение военных структур», «Полярис».

**Рассказы игроков** — 9 файлов, группа `group: Творчество игроков`, `order`
100+ (не перенумеровывать при вставках), перед блоком «Хроники войн»
(`#wars`). Текст переносится с лёгкой чисткой вёрстки 2008 года, сюжет не
переписывается.

**Механика группировки**: `HistoryChapterMeta` получает опциональное
`group?: string`. Отсутствие `group` = хроникальный поток как сейчас.
Оглавление рендерит подзаголовки групп; якоря — как у существующих глав.
Frontmatter-паттерны:

```yaml
# официальный канон (без АВБ)
title: Конверсия, Раскол, Регентство
order: 9
era: "4530–4600"
loreAuthor: tehnolog
credit: { work: "Новейшая история Империи" }

# рассказ игрока (мини-АВБ на кредит-чипе)
title: Красная ярость
order: 100
group: Творчество игроков
loreAuthor: avb
credit: { author: Rasher, work: Красная ярость, url: "http://www.robogear.ru/skelet/6/story_1.php" }
```

(Точная схема credit в .md-фронматтере — по действующему образцу кампаний;
если фронматтер не поддерживает объект — расширить парсер `src/lib/history.ts`
по образцу `campaigns.ts`.)

### 2. Атрибуция и реестр источников

`docs/ENCYCLOPEDIA_LORE_SOURCES.md`:

- **Запись 7**: «Новейшая история Империи» — официальный «Технолог», 2007;
  `loreAuthor: tehnolog`, `credit: {work}` без автора (автор не установлен —
  паттерн «Летописи: Звёздные герои»).
- **Запись 8**: секции Star Heroes — запись №6 («Летопись: Звёздные герои»)
  дополняется инвентаризацией секций со статусами: ✅ импортировано /
  ⏭️ вне скоупа с причиной / ⬜ очередь. Инвентаризация появляется в каждой
  записи, чтобы «обработан» больше не читался как «обработан целиком».
- **Запись 9**: творчество игроков — независимые авторы, `loreAuthor: avb` +
  именной `credit` с URL; мини-АВБ-марка.
- **Очередь** обновляется: истории героев Star Heroes — вне скоупа (решение
  2026-08-28); рассказы — убираются (импортированы); добавляется запись
  «статьи/описания войск robogear.ru — не импортированы: дублируют справочник».

Классификация фиксируется тестом `src/__tests__/lib/lore-credits-avb.test.ts`:
рассказы — `avb`, главы Империи — `tehnolog`.

### 3. SEO — находимость по «Робогир»

- `src/app/layout.tsx` keywords: добавить кириллические «Робогир», «вселенная
  Робогир», «легенды Робогир», «летопись Робогир» (латинский `robogear` уже
  есть).
- `/encyclopedia/history`: `metadata.description` и вводный абзац — «Хроника
  вселенной Робогир (Robogear) — общего мира настольных игр Робогир и
  Бронепехота».
- Лендинг: одно предложение в блоке энциклопедии про общую вселенную.
- Названия новых глав/секций («Новейшая история Империи», «Легендарные
  Имперские Лорды»…) — сами по себе поисковые хиты; `/encyclopedia/history`
  уже в sitemap.
- Вне скоупа (YAGNI): отдельный лендинг «Робогир», новые JSON-LD-сущности,
  правки `sitemap.ts`/`robots.ts`.

### 4. Поиск внутри приложения

Сейчас `/encyclopedia` (`src/components/encyclopedia/EncyclopediaPage.tsx`)
ищет только по `unit.name`/`unit.shortName`. Расширение — клиентский фильтр
без сервера:

1. **`src/lib/unit-search.ts`** — чистая функция `buildSearchHaystack(unit)`:
   name, shortName, имя фракции, `encyclopedia.manufacturer`,
   `encyclopedia.lore`, `encyclopedia.history`, `encyclopedia.tactics`
   (lowercase; haystack строится один раз, useMemo). Запросы «Робогир»
   (manufacturer «Робогир Индастриз»), «Долгорукий», «Велиан» находят юниты.
2. **`LoreSearchHints`** — строка чипов-ссылок над сеткой юнитов: совпадение
   запроса с заголовком главы/рассказа/кампании (по подстроке, ~30 названий).
   Серверная `page.tsx` передаёт список заголовков клиентскому компоненту
   (`getAllHistoryChapters()` синхронный, frontmatter-only).
3. Вне скоупа: полнотекст по телам глав, поиск по миссиям.

### 5. Оглавление, устойчивость, порядок работ

- Сортировка глав прежняя — по `order`; `group` только добавляет подзаголовок
  в TOC. Блок «Хроники войн» (`#wars`) остаётся завершающим.
- `group` опционален — старые главы не требуют правок; markdown-ошибки
  падают на build (существующий контракт статик-экспорта, видно в CI).
- Чистка вёрстки рассказов — скрипт-помощник при переносе + финальная
  вычитка глазами.

**Порядок работ**: (1) главы 9–11 из `legend_empire.pdf`; (2) секции
справочника из `Star_heroes.pdf`; (3) сверка «Легенд мира Робогир»;
(4) 9 рассказов; (5) реестр источников; (6) поиск (util + UI);
(7) SEO; (8) тесты/e2e. Каждый шаг — отдельный коммит `[type(scope)]`.

## Тестирование и приёмка

- **Юнит**: `history` — новые главы присутствуют, `group` резолвится, порядок
  9–11 после 8, рассказы (order 100+) перед `#wars`; `lore-credits-avb` —
  классификация источников; новый `unit-search.test.ts` (haystack по
  manufacturer/lore, регистронезависимость, подсказки по заголовкам).
- **E2E** (CI-only): страница Истории показывает главы 9–11 и группы; поиск
  «Робогир» находит технику; подсказка главы по запросу. Селекторы
  `getByTestId`, `clearStorage`, без фиксированных слипов.
- **Ручная приёмка**: вычитка новых глав на стилевое единство с 1–7;
  отсутствие дублей событий из «Легенд мира Робогир».

Обязательные проверки перед завершением: `npm run type-check`, `npm run test`,
`npm run test:e2e` (CI).

## Вне скоупа

- Истории героев Star Heroes («Пустотный Бой», «Призрак»…) — очередь реестра.
- Статьи и «Описание войск» robogear.ru — дублируют справочник.
- Летопись Протектората (HTML-заглушка) — пусто.
- Мультфильмы/anime, мобильная игра, Tales of Hazard — не лор энциклопедии.
- Полнотекстовый поиск по телам глав; новые роуты/табы.
